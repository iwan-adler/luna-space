# ADR 0014 — Chat (Phase 6)

- **Status:** Accepted
- **Date:** 2026-11-19

## Decisions

- **Tables:** one conversation per workspace: `messages`, `message_reactions` and
  `chat_read_state`, as in Schema §20. Attachments are `files` rows with a new `message_id`
  column. Clients can only add attachments to their own messages.
- **Editing and deleting:** an edit stamps `edited_at` (shown as "edited"). Deleting sets
  `deleted_at`, clears the text and metadata, and soft-deletes the attachments, all in a trigger
  (AC-21). Only the sender can do either; the column grants allow only `body` and `deleted_at`.
- **Read receipts** use one row per member. A message shows "Seen" when the partner's
  `last_read_at` is at or after it. `mark_chat_read` only moves forward, and it also clears chat
  notifications.
- **Notifications:** a new message creates at most one notification (and push) per 10-minute
  burst, with a dedupe key per 10-minute window, so a conversation doesn't flood the phone.
- **Live updates and presence:** messages, reactions, read states and attachment uploads update
  live through Realtime. Online/offline uses Realtime presence (nothing is stored), and the
  manual status (available, busy, focusing, away) uses `profiles.availability`.
- **Formatting:** messages render with the notepad's Markdown-lite renderer (React elements only,
  no raw HTML). Quotes and previews strip the formatting marks.
- **Guests:** project guests have no chat access. Project threads (FR-CHAT-09) and quick
  commands (FR-CHAT-10, R2) are not part of this change.
- **Shared helpers:** file helpers moved to `src/lib/files.ts`, so the chat badge in the app
  shell doesn't pull the projects feature into the first page load.
