# ADR 0001 — Phase 0 setup decisions

- **Status:** Accepted
- **Date:** 2026-11-17
- **Context:** Implementation Plan (docs/specs/03_impl.md) §2 and Phase 0.

## Decisions

1. **Libraries are added in the phase that first uses them**, not all at once as listed in
   Implementation Plan §2.4. Phase 0 installs only React, React Router, supabase-js, Tailwind,
   the self-hosted fonts and the test/lint toolchain. TanStack Query, Zod, React Hook Form,
   date-fns, dnd-kit, FullCalendar, Dexie, react-markdown and vite-plugin-pwa arrive with
   Phases 1–8. Reason: smaller bundle and fewer unused-dependency updates.
2. **Migration file names use the Supabase CLI timestamp format**
   (`20261117000001_extensions.sql`) instead of `0001_extensions.sql`. The logical order still
   follows Backend Schema §30; the first migration corresponds to row 0001.
3. **Specifications live in `docs/specs/`** as Markdown. PDFs are generated by
   `tools/docs-pdf` into `planning/` (git-ignored) so the Markdown is the single source of truth.
4. **Playwright uses the locally installed Chrome** on developer machines (`channel: 'chrome'`)
   and Playwright's Chromium in CI, avoiding a browser download on laptops.
5. **The Supabase client is optional at runtime**: when `VITE_SUPABASE_*` variables are missing
   the app still renders and explains what is missing. This keeps CI builds and fresh clones
   working without secrets.
6. **Local Supabase auth config is hardened from the start**: email confirmation required and
   minimum password length 10 (PRD FR-PLAT-01, TRD §6.1). The hosted project must be configured
   the same way in the dashboard (Implementation Plan §5.2).

## Consequences

Each later phase's first PR installs its own libraries and records them in `CLAUDE.md` if they
change conventions.
